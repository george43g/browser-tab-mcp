# tmux-control application library

Phase 3 / M2 and Phase 4 / M3 are read-only slices. `adapter/read.ts` is the sole tmux process boundary. It passes argv arrays to `tmux`, asks for `-F` rows, and parses them into a snapshot. The model distinguishes a session's window **slot** (`$session:@window`) from the underlying window (`@window`), because one window can be linked into several sessions. Panes belong to the underlying window and appear once in the snapshot.

`makeTmuxDomain(snapshot)` binds this model to `@george43g/control-language`. M3 chose the slot-as-entity candidate: each slot has one session parent and one sibling run, while a shared window remains a separate global object with no session parent. Global window objects are ordered by numeric `@id`, independent of which linked session tmux lists first; their panes follow that object order. Session window order is available through slots only. All 17 selector kinds pass M1's conformance suite on captured real `-F` output; linked-window and session-group tests cover the four sibling-dependent kinds. The resolver algorithm remains unchanged. The core's unused `occurrenceId` and constant `projectionId` metadata were removed because stable slot keys now identify each ordered appearance.

`previewSplitImpact(snapshot, slotKey)` names every other slot that shares the window. For example, splitting through `presentation` also changes window `@N` as seen in `claude`, because both slots contain the same window and panes. This is a read-only impact description for M3's acceptance case; the effectful split verb and planner belong to later phases.

The adapter compares server identity, session rows, client rows and structural window/pane rows across two reads. It rejects a concurrent structural change and validates every session, slot, window, pane and client reference before returning. This is a best-effort read boundary; M5 will add the snapshot token used to refuse a stale *apply*.

The `project` predicate field is the nearest Git checkout's repository name. For a linked worktree, the adapter follows the `.git` pointer to the common repository directory, so a pane in `tmux-m2` still reports `browser-tab-mcp`. If no Git checkout exists, the field is absent.

Existing tmux libraries and MCP servers were evaluated in the approved plan's §13. `libtmux` is the closest TypeScript library; this slice uses direct `-F` reads because its purpose is to prove this repo's existing selection core over a small, inspectable tmux model, without adopting another tool's object identity or 45-tool surface. M3 added no dependency: tmux itself supplies linked-window and session-group identities, and the existing control-language resolver already handles distinct slot keys.
