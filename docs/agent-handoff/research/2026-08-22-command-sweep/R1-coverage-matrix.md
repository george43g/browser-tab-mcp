# R1 — Factual coverage matrix: every tool + CLI subcommand vs. actual test layer

Method: enumerated tools from `apps/browser-tab-mcp/src/tools/registry.ts` (20 tools,
confirmed against `apps/browser-tab-mcp/tests/registry.test.ts:11-30`) and CLI
subcommands from `apps/browser-tab-mcp/src/cli.ts` + `apps/browser-tab-mcp/src/commands/daemon.ts`,
cross-checked against `apps/browser-tab-mcp/.usage.kdl`. **No disagreement found** between
`cli.ts` and `.usage.kdl` — every `cmd`/`cmd { cmd }` in the kdl file has a matching
`.command()` in `cli.ts` and vice versa (top-level: mcp, tui, doctor, repl/console, health,
bookmark/bm, logs, list, reload-extension, journal, history, page, annotate, screenshot,
focus, close, open, move, act, group, window{open,set,close}, daemon{run,install,uninstall,
status,token,stop,restart}, noop).

**Critical layer-classification rule applied throughout**: `installFakeChrome` (from
`@george43g/test-kit`) and `BROWSER_TAB_FAKE_ADAPTER=1` both stand in for a browser —
neither is a real browser. Every test using either is marked **dispatch-only**, no matter
how many real production components (daemon, WS server, IPC, extension-core) sit between
the call and the fake. **`effect-verified` is reserved for the 3 Playwright tests in
`apps/chrome-extension/e2e/*.e2e.test.ts`**, which drive a real headless Chromium (or, on
the Windows `e2e-branded` CI leg, real Chromium/Edge channels) — the only place any browser
actually does anything.

A second finding, orthogonal to fake-vs-real: **the entire AppleScript/osascript code path
has zero test coverage of any kind against a real macOS Automation call.**
`apps/browser-tab-mcp/src/detect/adapters/focus.test.ts:9,16` states outright: "osascript
can't run in CI" and mocks the `runOsa` function completely. Every AppleScript-adapter unit
test mocks `osascript`; every fake-adapter integration test substitutes a JS fixture for
AppleScript output. No test anywhere spawns real `osascript` against a real Chrome/Safari
window. This means `list_tabs`/`focus_tab`/`tab_action`(navigate/reload/back/forward)/
`open_tab`/`open_window`/`set_window`'s AppleScript pathway, `doctor`'s TCC probing, and the
window-tier `screenshot`'s `screencapture` invocation are dispatch-only even where the tool
itself has "real socket" tests — those real-socket tests exercise the **extension** pathway
only (via `installFakeChrome`), never the AppleScript pathway with a real browser.
