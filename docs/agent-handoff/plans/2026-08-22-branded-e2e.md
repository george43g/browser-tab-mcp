# Branded-browser e2e (Windows Chrome + Edge) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Parameterize the existing Playwright e2e suite by browser channel so it runs against real branded Chrome and Microsoft Edge, and add an unconditional `e2e-branded` windows-latest CI job covering both.

**Architecture:** One env knob (`E2E_BROWSER_CHANNEL`) threads through the existing fixtures; the expected browser id is derived from the channel and replaces every hardcoded `chrome` literal in assertions. Config seeding stops pinning the browser id so the extension's real UA auto-detection (`detectBrowserName`) is what each leg exercises — the msedge leg thereby becomes the standing regression test for the `edg/`-before-chrome ordering that prevents Edge evicting the Chrome WS session. CI gets a two-row matrix job on windows-latest using the preinstalled branded browsers (no Playwright download).

**Tech stack:** Playwright ^1.61.1 (`channel: "chrome" | "msedge"`), GitHub Actions windows-latest.

**Spec:** George's directive 2026-08-22 (approved plan `~/.claude/plans/optimized-toasting-lynx.md`): live-verify Windows Chrome + Edge, add them to CI, keep everything headless.

## Global Constraints

- Existing `e2e-chromium` (ubuntu) job stays byte-identical.
- All legs stay headless (`--headless=new`); no xvfb, no headed mode anywhere.
- `seedConfig` must NOT write a `browser` key — auto-detection is the behavior under test.
- Default behavior with `E2E_BROWSER_CHANNEL` unset must be exactly today's (channel `chromium`, expected id `chrome`) so the ubuntu job is untouched semantically.
- Repo rules: any `src/**` change needs a README touch (A3 covers it); never write to stdout after transport connect (not applicable — test/CI code only).

### Task 2: `e2e-branded` CI job

**Files:**
- Modify: `.github/workflows/ci.yml` (append a job after `e2e-chromium`; do not touch `e2e-chromium`)

**Steps:**

- [ ] **Step 1: append the job.**
  ```yaml
  # Branded-browser e2e: the SAME three tests against real Google Chrome and
  # Microsoft Edge on Windows — both preinstalled on windows-latest, reached
  # via Playwright's channel option, so there is no browser download at all.
  # The msedge leg is the standing regression test for detectBrowserName's
  # edg/-before-chrome ordering (Edge must not evict the Chrome WS session).
  e2e-branded:
    name: e2e (${{ matrix.channel }}, windows)
    runs-on: windows-latest
    timeout-minutes: 20
    strategy:
      fail-fast: false
      matrix:
        channel: [chrome, msedge]
    steps:
      - name: Checkout
        uses: actions/checkout@v6
      - name: Setup pnpm
        uses: pnpm/action-setup@v6
        with:
          version: 10.29.3
      - name: Setup Node
        uses: actions/setup-node@v6
        with:
          node-version: "24"
          cache: pnpm
      - name: Install dependencies
        run: pnpm install --frozen-lockfile
      - name: Build (extension bundle + daemon CLI)
        run: pnpm build
      - name: Run e2e against branded ${{ matrix.channel }}
        run: pnpm --filter @george43g/chrome-extension test:e2e
        env:
          E2E_BROWSER_CHANNEL: ${{ matrix.channel }}
      - name: Upload Playwright report on failure
        if: failure()
        uses: actions/upload-artifact@v7
        with:
          name: playwright-report-${{ matrix.channel }}
          path: |
            apps/chrome-extension/playwright-report/
            apps/chrome-extension/test-results/
          if-no-files-found: ignore
  ```
  Note: NO `Setup Rust` step (windows-latest preinstalls a toolchain; the guarded build script copes either way) and NO playwright install step — if the run proves Chrome/Edge are missing from the image after all, ADD `pnpm --filter @george43g/chrome-extension exec playwright install ${{ matrix.channel }}` rather than downloading chromium, and note it in the report.
- [ ] **Step 2: yaml sanity** — `node -e "const y=require('js-yaml');y.load(require('fs').readFileSync('.github/workflows/ci.yml','utf8'))"` (js-yaml may not be installed; `pnpm exec prettier --check` also parses yaml — otherwise rely on actionlint if present, else visual check + CI itself).
- [ ] **Step 3: commit** — `git commit -m "ci: e2e-branded — the 3 Playwright tests against real Chrome + Edge on windows-latest"`.
